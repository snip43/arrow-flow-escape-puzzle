# STAGE 1D.2 — главное меню, выбор уровня и навигация

Базовый коммит — `7a375478f987c2c06bb4389c60421102b5e4ce81`. Обычный запуск теперь открывает главное меню. Play запускает Tutorial 1, Continue показывает номер следующего непройденного уровня. После сотой победы меню предлагает Replay levels. В селекторе доступны все 100 карточек для просмотра. Статусы Open, Cleared и Locked различимы по тексту, доступное новое поле выделено мятным цветом.

## Маршруты и прогресс

| Действие | Результат |
|---|---|
| Главное меню → Play / Continue → Back | Возврат в главное меню |
| Главное меню → Levels → доступная карточка → Back | Возврат в селектор с актуальными статусами |
| NEXT LEVEL после победы | Открывается следующий уровень. Маршрут для Back сохраняется |
| Back в процессе движения | Текущая попытка завершается, обработка указателя отключается, tween отменяется. При следующем входе поле полное |
| Restart после победы | Начинается новая попытка того же уровня, победа остаётся в прогрессе |
| Escape или системный Back | В игре и селекторе действует как Back. В корне приложение остаётся в главном меню |

[CampaignSession](../game/campaign_session.gd) принадлежит экземпляру корневой сцены. Завершённые уровни всегда образуют непрерывный диапазон от 1 до N, поэтому достаточно хранить длину этого диапазона. Маршрутизатор проверяет ID до создания игровой сцены. Завершение регистрируется по сигналу активной сцены после удаления последней стрелки из модели. Только завершение уровня N+1 увеличивает счётчик. Полный перезапуск приложения начинает новую сессию с нулевым прогрессом; возврат между экранами сохраняет все победы в памяти.

При выходе игровая сцена удаляется из дерева и освобождается. За меню отсутствуют активное поле и его обработчик ввода. Номер поколения защищает новую попытку от старого callback. Для изолированных тестов игровой экран по-прежнему можно создавать напрямую. Кнопку Back показывает маршрутизатор; она расположена слева от Restart в ранее свободном нижнем ряду.

**Всего 2 267 успешных проверок.** Прежние наборы тестов сохранены. В 1C два ожидаемых предупреждения вызваны проверками недопустимого ID. В процессе разработки тест выявил, что фильтр двойного системного Back мог пропустить новую команду после отдельного клика в том же кадре. Для нового нажатия фильтр сбрасывается. Итоговые проверки подтверждают один переход при парном Escape / системном уведомлении и возврат по следующему самостоятельному действию.

Новый набор проверяет все 100 ID, группы, закрытые и повторно доступные карточки, достижимость последнего ряда, открытие при клавиатурном фокусе, прокрутку колёсиком и отмену навигации при multitouch. События мыши проходят через viewport. Одиночное программное касание проходит через Input с эмуляцией мыши самим Godot. Тесты проходят Tutorial через контроллер, проверяют границы 20→21, 60→61, 99→100 и финал. Для ускорения граничных проверок предыдущие победы подготавливаются только в тестовой сессии. Сами проверяемые победы проходят через движение, commit и сигнал. Отдельно проверены отказ, Restart, частичный ход и выход во время активного tween.

### Ручная проверка на Windows

1. Запустить `godot --path .`, открыть Levels и прокрутить до 100. Вернуться к началу и открыть 1. Закрытая карточка должна оставить пользователя в списке.
2. После удаления одной стрелки нажать Back, затем снова открыть 1. Проверить полное исходное поле. Выйти в меню и открыть Tutorial кнопкой Play.
3. Закончить Tutorial и нажать Back. В меню должны появиться Continue · Level 2 и 1 / 100 completed. Открыть Levels, переиграть 1 и проверить, что счётчик остаётся равен 1.
4. На экране победы выбрать NEXT LEVEL, затем Escape. Проверить возврат к тому экрану, откуда начиналась игра. Закрыть и заново запустить приложение для проверки новой сессии.

### Ограничения и дальнейшие этапы

Для физического Android остаются проверка системного Back, реального жеста прокрутки, вырезов экрана и удобства касания. Измерения в пикселях окна не определяют физический размер в dp. Постоянное хранение прогресса относится к STAGE 1E.1. Экономика, реклама, покупки и другие коммерческие функции находятся за пределами STAGE 1D.2.
