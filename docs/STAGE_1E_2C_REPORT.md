# STAGE 1E.2C — аварийное восстановление оплаченной попытки

База принятого этапа — `62d9b794d0a02891dd663a74e03fe2b41e51342e`, ветка `main`. Исходное дерево было чистым. В 26 испытаниях Windows принудительно завершала процесс Godot на заданной границе. После kill сразу за rename следующий процесс восстановил Hint с остатком 210 Coins либо Continue с остатком 165 Coins и одной жизнью. Ещё один запуск каждого профиля оставил баланс, ревизию, квитанцию и поле прежними.

## Сохранение и маршрут игрока

| Событие | Авторитетное состояние |
|---|---|
| Покупка Hint / Continue | Одна публикация объединяет уменьшение кошелька, квитанцию и стабильное состояние поля с результатом покупки. Только подтверждённая запись разрешает выдачу в работающей сцене |
| Перезапуск | С checkpoint открывается оплаченный уровень. Восстанавливаются клетки, выделение, ошибки, жизни и исходный маршрут Back. Без checkpoint открывается меню. Загрузка ничего не записывает |
| Начало выхода стрелки | Пока движется хвост, на диске остаётся предыдущая стабильная доска |
| Полный выход хвоста, ошибка или поражение | В оплаченной попытке публикуется следующая ревизия с тем же кошельком и квитанцией. У обычной неоплаченной попытки запись на каждый ход отсутствует |
| Следующая покупка | Требует отдельного нажатия. Новый ID операции и новый эффект заменяют предыдущие в одной транзакции |
| Победа | Новый префикс, фактическая награда и удаление checkpoint фиксируются вместе. Replay закрывает попытку с нулевой наградой |
| Явный Back / Restart | Checkpoint удаляется отдельной подтверждённой записью до ухода или сброса поля. Плата за покупку остаётся израсходованной |
| Отказ сохранить ход или победу | Поле возвращается к последней подтверждённой доске. При доказанном отказе можно повторить ход. При неопределённом результате дальнейшие траты замораживаются до перезапуска |
| Отказ сохранить отказ от попытки | Игра остаётся на поле. При временном отказе видна надпись `Board still saved. Retry Back or Restart.` После устранения препятствия игрок может бесплатно повторить действие |

Обработчик покупки проверяет сцену, поколение команды, состояние попытки, lifecycle, остаток, dirty и блокировки хранилища. Вложенные траты и навигация исключены на время синхронной операции. До публикации формируется отдельный кандидат. Проверяются ожидаемый базовый снимок, записанные байты временного файла после flush/close и полный снимок после rename. При потерянном ответе подтверждением служит перечитывание слотов. Неопределённый результат не запускает автоматическое повторное списание.

## Схема v3 и миграция

В прежних двух слотах остаются `schema_version`, `revision`, `campaign.completed_count` и `wallet.coins`. Необязательный объект `checkpoint` существует только до окончания или явного сброса оплаченной попытки.

| Поля checkpoint | Что проверяется |
|---|---|
| `catalog`, `level`, `origin` | SHA-256 установленного каталога, доступность уровня 2–100 по префиксу кампании, маршрут menu/levels |
| `removed` | Упорядоченные ID. На свежей BoardModel из каталога каждый выход должен быть легален в момент удаления. Повтор, неизвестный ID, невозможный порядок и пустая итоговая доска отклоняются |
| `lives`, `errors`, `state` | Целые значения, соответствие числу ошибок и ACTIVE/FAILED. После третьей ошибки допустимы 0 или 1 жизнь. На поле в FAILED должна оставаться заблокированная стрелка |
| `used_hint`, `hint` | Булев признак и текущий доступный детерминированный ID либо пустая строка |
| `kind`, `operation` | hint/continue и случайный 128-битный ID из 32 шестнадцатеричных символов. Продолжение требует предшествующего поражения |

Физических координат, объектов сцены и tween в записи нет. Ограничение слота — 16 КиБ. История ограничена 100 ID и фактическим числом стрелок на поле. Прежние пределы ревизии и баланса сохранены. Для v3 валидатор строит типизированный документ с целыми числами в исходном порядке ключей и сравнивает с исходной JSON-записью с учётом пробелов. Эта проверка выявляет дубликаты, лишние поля и запятые, дроби и потерю точности при JSON-разборе. Числа v3 записываются десятичными целыми. Варианты числовой записи v1/v2 обрабатываются прежними валидаторами.

V1 открывается с прежним N, ревизией и стартовыми 50 монетами. V2 передаёт точный остаток. При чтении ни один слот не переписывается. При первой транзакции создаётся v3 только в неактивном слоте. В тестах миграции N=42 и ревизия 83 сохранились при чтении, покупка создала ревизию 84, старый слот остался побайтно прежним.

При выборе последнего валидного снимка, сравнении ревизий и проверке ожидаемой базы учитывается и checkpoint, включая ID операции. При равенстве ревизий выбор консервативный — меньший N, затем меньший баланс, затем первый слот. Разные квитанции или поля при одинаковом кошельке вызывают диагностику конфликта. При повреждении нового слота восстанавливается прежний целостный снимок с предупреждением. Повреждение или конфликт блокирует новые траты, в том числе при обнаружении непосредственно перед публикацией. Перед повторным использованием повреждённого или вытесняемого конфликтующего слота проверяется архив его байтов. Неизвестная будущая версия и ошибка чтения блокируют запись.

## Испытания с внешним завершением процесса

Каждый сценарий использует свой `af_test_<GUID>`. Writer доходит до нужной границы и публикует маркер с PID и ожидаемым результатом. Runner проверяет маркер и вызывает `Process.Kill()` на созданном им процессе. Каждый из двух следующих процессов открывает один и тот же профиль, сверяет дисковый снимок, кошелёк и реальную сцену, включая оставшиеся клетки, жизни, ошибки, подсказку и маршрут Back. В конце проверяется отсутствие дополнительной записи. Отдельный процесс очищает только свой профиль.

| Граница | Что проверяли |
|---|---|
| before / prior | Проверенный временный файл ещё не переименован. В первом случае сохраняется прежний кошелёк без новой попытки. Во втором остаётся прежняя оплаченная попытка |
| renamed | Слот опубликован, приложение ещё не получило подтверждение |
| confirmed | SaveStore подтвердил запись, управление ещё не вернулось в код выдачи эффекта |
| applied | Контроллер уже применил эффект |
| motion / stable | Следующий выход стрелки ещё анимируется либо удаление уже подтверждено |
| win-before / win-after | До и после публикации награды и удаления checkpoint |
| back-before / back-after, restart-before / restart-after | До и после публикации явного отказа. Баланс в обоих случаях одинаков |

## Границы проверки

Испытания воспроизводят аварийное завершение **процесса** при работающей ОС и доступной файловой системе. Физический Android, внезапное отключение питания и одновременная запись нескольких экземпляров игры в один профиль не испытывались. Повреждение последнего слота может откатить весь снимок к предыдущей ревизии. Утрата обеих копий исключает гарантированное восстановление. Защита предназначена для локальных Coins. Реальные IAP требуют доверенной проверки транзакций магазина и идемпотентной выдачи покупок в отдельном этапе.
