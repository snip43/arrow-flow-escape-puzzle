## Экспорт на Windows

Использованы установленные Godot `4.3.stable.official.77dcf97d8`, шаблоны `4.3.stable`, Microsoft OpenJDK 17.0.20, Android SDK Platform 34, platform-tools 34.0.5. Экспортёр использовал build-tools 34.0.0 для подписи, независимая проверка использовала aapt и apksigner из 36.0.0. Импорт, экспорт, проверка манифеста, архива и подписи завершились с кодом 0.

[Preset](../export_presets.cfg) экспортирует главную сцену, её зависимости и JSON-каталог штатным экспортёром Godot. [PowerShell runner](../tools/export_android_debug.ps1) копирует игровые ресурсы во временный проект и использует отдельные настройки редактора. В архиве проверено отсутствие `assets/tests`, `assets/docs` и `assets/tools`. Для повторения из корня проекта передайте путь к локальному Godot. При нестандартной установке доступны параметры `-AndroidSdk`, `-Jdk`, `-Templates`, `-DebugKeystore`.

```powershell
.\tools\export_android_debug.ps1 -Godot $GodotConsole
Get-FileHash .\build\android\arrow-flow-debug.apk -Algorithm SHA256
```

До включения импорта ETC2/ASTC валидатор Godot 4.3 отклонял проект для Android. После включения импорт прошёл. Следующий экспорт подписал APK, но сообщил `ERROR: No project icon specified`. В проект добавлен [значок](../ui/android_icon.svg) с геометрией и цветом существующего знака из меню. Повторный экспорт прошёл без ошибок. Runner проверяет и код процесса, и сообщения об ошибках. [Проверка конфигурации в исходниках Godot 4.3](https://github.com/godotengine/godot/blob/4.3-stable/platform/android/export/export_plugin.cpp#L2380).

На первом запуске APK в AVD статическая разметка меню появилась без работающих кнопок. В logcat процесса Godot обнаружены ошибки загрузки GDScript. Режим экспорта только выбранной сцены пропустил зависимости, загружаемые из скриптов. Финальный preset явно перечисляет игровые ресурсы, а runner проверяет наличие каждого GDScript в готовом APK.

На Android 14 при дисплее 720×1280 правая граница кнопок находилась на x=480, подпись перекрывала прогресс. Причиной было использование физических размеров safe area как логических координат растянутого корня. В мобильной ветви [safe_layout.gd](../ui/safe_layout.gd) отступы теперь вычисляются по пересечению безопасного прямоугольника с окном и отношению логического размера к размеру окна в пикселях. Минимальные отступы, шрифты, размеры кнопок и исходные сцены сохранены. [Кадр до исправления](screenshots/stage_1f_1/00_before_safe_area_emulator.png).

[Тест пересчёта](../tests/stage_1f_1.gd) покрывает весь экран 720×1280, системные отступы, смещённое окно, пустую безопасную область и прямоугольник шире окна.

Сцены, тема, BoardModel, TapTracker, экономика, каталог, генератор, Solver и схема SaveStore v3 совпадают с базой. Уровень 1 допускает неограниченное число ошибок. На уровнях 2–100 три жизни. Начальный баланс 50, Hint стоит 30, Continue стоит 75 и возвращает одну жизнь. Награда за первое прохождение и бонус Perfect +5 покрыты регрессией.

## Эмулятор Android

Для прогона создан отдельный временный AVD ArrowFlow1F1. Android Emulator 32.1.15, профиль Pixel 5, системный образ Android 14 Google APIs, API 34 rev. 8, x86_64, WHPX, OpenGL ES 3.0 SwiftShader. Дисплей по `wm size` — 720×1280 px, `wm density` — 320 dpi, то есть 360×640 dp. Режим системной навигации 2 (жесты). Приложение использует immersive mode. На первых запусках до испытания профиля `files/arrow_flow` в пакете не существовало.

Окончательный APK установлен штатным `adb install -r` поверх предыдущей отладочной сборки в этом AVD. Исправленное меню занимает доступную ширину. На изображении Play — приблизительно 656×115 px (328×57,5 dp), боковые поля — 32 px (16 dp). На игровом поле высота нижних кнопок — около 107 px (53,5 dp), ширина Back — 140 px (70 dp). На этом дисплее подписи видны полностью.

Для повторения используйте новый AVD с указанным именем, разрешением, плотностью и образом. Запустите его, дождитесь загрузки Android, затем выполните из корня проекта:

```powershell
python -B tests/android_stage_1f_1.py --adb $Adb --serial $EmulatorSerial
```

[Сценарий Android](../tests/android_stage_1f_1.py) сверяет имя, тип и геометрию AVD и требует чистой установки. Он посылает Android input-события, читает данные только своей debug-сборки через `run-as` и записывает неизменённый вывод `adb exec-out screencap -p`. Перед каждым сравнением после force-stop проверяется запуск нового процесса. Для двухпальцевого жеста сценарий компилирует [тест UI Automator](../tests/android/TwoPointerTest.java) средствами установленного JDK и build-tools 34.0.0. Для запуска проверок через отдельный сервер ADB предусмотрен параметр `--server-port`. Итоговые проверки восстановления и мультитача выполнены через выделенный локальный порт, код 0.

## Физический Android

**NOT RUN.** Нет результата установки на физический ARM64-телефон, проверки вырезов и системных панелей реальной модели, эргономики касаний и двух пальцев, аппаратного поворота, фонового режима и восстановления покупок на его накопителе. Эти пункты остаются на мобильную приёмку.

Для установки подключите один авторизованный телефон и выполните из корня проекта `.\tools\install_android_debug.ps1`. [Runner установки](../tools/install_android_debug.ps1) проверяет число транспортов, состояние авторизации, тип устройства и существование пакета, включая сохранённые данные удалённого приложения. При чистом профиле он установит и запустит уже собранный APK. Если обнаружен существующий профиль, он останавливается до установки. Защита при нескольких ADB-транспортах проверена отдельным запуском — runner остановился до установки. Для аварийных испытаний требуется отдельный тестовый профиль.
